# 强化学习模板：标准引导 + 迭代改良

> 不是一次性学成功，而是**有标准方法做引导，在反复使用中逐渐优于标准**——吸收优点，剔除缺点。

本仓库的倒车入库就是按这个模板做的。以后换任务、换动作、换标准方法，都只改模板的空位。

## 五步循环

```
① 标准方法（老师）
     给出一批能用的解（能到，但可能有冗余）
        ↓
② 收集"缺点"样本
     对每条解逐动作试删 → 记录 (动作特征, 可删?)
        ↓
③ 学出规则
     统计每个特征值的可删率 → "位置=最后一个 → 可删率 60%"
        ↓
④ 应用 + 验证
     命中规则的动作先删 → 跑一次验证；不成就回退
        ↓
⑤ 迭代
     新样本不断进来，规则库越来越准，删得越来越快
```

## 实测效果（倒车入库）

| 方法 | 成功率 | 平均动作 | **验证次数** |
|---|---|---|---|
| 标准方法（束搜索） | 10/10 | 8.1 | 10 |
| **学到的规则** | **10/10** | **7.5** | **10** |
| 逐个试删（穷举） | 10/10 | 7.5 | **103** |

**同样短（7.5 个动作），但验证次数只有穷举的 1/10。**

学到的规则（示例）：

```
位置 = last  →  可删率 60%（20 次样本）
```

## 三个空位（换任务只改这三处）

| 空位 | 倒车入库里的实现 | 换成别的任务时 |
|---|---|---|
| **标准方法** | 束搜索 | 任何现成的规划器/教科书算法 |
| **动作特征** | 方向/转向/长度/位置/离目标 | 你任务里"什么情况下这个动作可能多余" |
| **评估函数** | 是否入库 + 动作数 | 成功判据 + 成本 |

## 为什么这样算"强化学习"

| 强化学习的要素 | 模板里的对应 |
|---|---|
| 状态 | 当前姿态（离散化后） |
| 动作 | 基本动作（方向×转向×弧长） |
| 奖励 | 成功 / 动作数减少 / 碰撞惩罚 |
| **学习** | 从每次试删里积累"哪类动作可删"的规则 |
| **强化** | 规则库越大，删得越准、越快，效果越来越强 |

**关键区别**：不是从零探索，而是**在标准方法的解上不断改良**。
标准方法保证起点不会太差，学习负责把冗余挑出来——
这就是"吸收优点、剔除缺点"。

## 可继续加强的地方

1. **规则更细**：现在是单特征，可以学特征组合（数据够多时）
2. **规则可撤销**：某条规则多次失效就降权（现在是一次验证就回退）
3. **规则跨任务复用**："最后一个动作常冗余"这种规律可能在多个任务里都成立

## 代码

| 文件 | 作用 |

运行：

```bash
cd garage
python pattern_learn.py     # 约 5 分钟，输出规则与三种方法对比
```
